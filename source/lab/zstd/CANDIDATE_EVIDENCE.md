native and external CLI are both zstd1.5.7: separate producer artifacts, not independent codec implementations. a manually structured raw frame independently anchors literal `abc`; independent PNG pixels and literal packet encodings supplement the frozen native stream.

full-width native codec returns, wrapping native arithmetic, do-at-least-once empty streams, full-output continue before completion, append prefixes and distinct completion conditions are covered. decompression ends on consumed input alone, not frame completion. output growth is not transactional; failed tails are inspected only with preinitialized genuine backing allocations and checked extents. aliases are limited to live capacity-stable domains.

controlled return/status and smaller output-span cases are explicitly counterfactual. resize injection follows real codec progress, preserves exception identity and later reuse of the same handle, but is NOT actual oom or universal allocator/destructor timing evidence. native host/callback observations never delegate a whole legacy controller.

## actual native image and TCP consumers

`build/behavior/zstd-actual-r1/report.json` passed two independent all-C++ baselines before the combined Rust candidate. all three1000x600 frames have zero changed pixels/error, exact normalized state/bytes and occluder restoration. all three candidate PNGs were inspected: normal orange64x64 image, normal white `ZSTD` Font label, visible wall/light change and restoration. no synthetic replacement capture or image repaint.

actual flow:

1. normal postLoad image operations create16x16 RGBA224/160/64/255; `image:embed("Zstd")` calls native PNG writing and the selected one-shot compressor.
2. two real native `TcpSocket`/`TcpPacketSocket` endpoints, bound only to127.0.0.1, exchange actual `ChatSendPacket` objects across persistent Zstd streams. version5/stream enablement is configured manually: **not Universe handshake or multiplayer gameplay**.
3. the actual received embedded path drives the first uncached normal Assets PNG decode. actual received label drives Font rendering; actual decoded pixels drive the normal Drawable.
