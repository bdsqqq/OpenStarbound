## what the native observations establish

- fresh smaller/larger sizes, fixed role identity, real role inversion, and the
  minimum-eight allocation consequence when extension grows the result.
- noncopyable lvalue-qualified combiner invocation, proxy conversion/destruction
  event order and its effects on later iterations/tail.
- same token identity after direct callback or conversion failure, with prior
  live-input mutations retained and no failed-result read.
- nested combineWith on the same owner with fresh callback state.
- valid last-callback deletion of either the larger rhs or the larger receiver;
  only the smaller input and fully written result are inspected afterward.
- shrinking without extension leaves an unwritten result suffix: only its known
  prefix is serialized, never invented zeros or a whole-buffer comparison.

all input physical backing is initialized through public APIs before logical
shrinking. source/model review checked null/zero memory calls, pointer lifetimes,
role inversions, proxy cleanup, token lifetime and result-prefix bounds. these
are finite cases, not universal lifetime, allocation, free, OOM or sanitizer proof.

private destination-store versus proxy-destructor ordering is not independently
instrumented by this fixture. the requirement to keep callback, conversion,
destination lookup/store and temporary destruction in one native assignment leaf
is traced to the original full expression, not inferred from matching traces.
`DESIGN.md` records that seam and remaining constructor/inline-coherence decisions;
it is a design, not an implemented/accepted ABI.
