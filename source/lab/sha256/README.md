# frozen legacy sha256 laboratory

this oracle preserves the implementation's unusual contracts instead of replacing them with standard-library semantics. full original cpp/header bytes come from git `19506189`; adaptation changes only namespace/imports/header include. the Tom St Denis attribution and complete algorithm/class bodies remain. the reference never reads the actively edited implementation.

```sh
python3 source/lab/sha256/run.py --output build/sha256-lab/cpp-replay
python3 source/lab/sha256/run.py --output build/sha256-lab/rust-replay \
  --define STAR_USE_RUST_SHA256 \
  --archive build/sha256-rust/cargo-target/release/libstar_engine_ffi.a
```

the backend define/archive must be paired; arbitrary defines and outputs outside the owned build directory reject. flags are borrowed from the real reference native compile database's `StarSha256.cpp` entry: xcode clang, arm64, macos sdk, `-O3 -ffast-math`; both implementations receive the same flags, with dead stripping and undefined-behavior sanitizer added. no formulas or tolerances are changed. dead stripping permits full source compilation without pretending the core allocation libraries were linked.

`report.json`, `before.json`, `after.json`, compiler logs and per-control logs bind checker, frozen/candidate source, compile database, commands, selected archive and binary hashes. before/after input drift rejects the run. baseline must pass twice identically before any mutants count. expected facts are never regenerated by the runner.

## observable coverage

- all two-part splits for lengths 0–193; all nonempty chunk compositions for lengths 1–12; 1,000 randomized multi-chunk streams and 2,000 random two-part streams (fixed seed).
- actual public raw-pointer class construction, push, destructive repeated compute, empty/null push reset, copy and assignment forks before/after finalization.
- semantic chaining words, length, curlen, active buffer prefix and private finished flag through a lab-only observer. inactive/uninitialized tails are NEVER compared or initialized in the reference.
- raw one-shot overlaps at output offsets 0, 1, 31, 63; initialized input/state and output/state alias fallbacks; defined `size_t` narrowing with effective lengths 0 and 3, without giant allocations or signed-negative countdown.
- structurally valid seeded length-wrap states, every active prefix length 0–63, repeated finalization and reset. these are injected states, NOT claims of hashing an actual 512 mib message.
- rust-only: scoped successful update/final/reset receipts, alias/large-domain fallback exclusion, error state/output transaction probes, invalid shape, rejected abi aliases, and independent-thread receipts.
- 261 normal-domain rows checked against python `hashlib`; two published anchors independently extracted from official rfc 6234 §8.5 (definitions page 92; sha256 rows page 97). `published.json` records messages, digests, url and downloaded document identity. repository `sha_test.cpp` is NOT labeled a nist source.

`independent.py` derives constants from integer prime roots and computes the seeded wrap counterexample. retaining a 64-bit length would produce a DIFFERENT digest: compatibility requires the legacy zero high-length word. a mutation that writes that carry bit rejects at the intended seeded comparison.

## limits

public header, ordinary utf8/bytearray forwarding and allocating one-shot suffix are byte-preservation-gated. allocating class `compute()` preserves its allocation-before-mutation body, permitting only the backend call name change. these are SOURCE checks, not runtime allocation, utf8, same-bytearray resize/alias or allocator-failure tests. real core ownership libraries, btree database, assets transcript, native game, platform matrices, and cryptographic security are outside this laboratory's claim. the parent separately completed bounded actual Assets/database/game acceptance; see [EVIDENCE.md](EVIDENCE.md). those checks do not establish authentication, existing-save, cross-platform or universal equivalence.
