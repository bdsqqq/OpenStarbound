# instrumented recursive removal

INSTRUMENTED ONLY. This is a non-destructive, finite native calibration, not OS
successful-deletion evidence and not Rust or production qualification.

`calibrate.py` verifies the pinned parent receipt against current inputs, reuses
its coherent 113-object recipe, and substitutes only the unix File object. The
portable original remains the parent's byte-exact full compiled translation
unit. The generated platform copy replaces the exact static remove body once;
an extern declaration is local to that body, so all other bytes are identical.
The link plan and actual object table exclude the original platform object;
the final executable must contain exactly one strong static remove definition.
Native File layout, public header, String, IODevice and dependencies are retained.

The replacement calls the recording leaf unconditionally. It never falls back
to libc removal. Events contain call ordinals and hex-encoded native path bytes.
The controlled C++ exception is retained by exception_ptr; its caught address
must equal the address captured at creation. No exception crosses Rust.

The oracle is derived from StarFile.original.cpp:16–34. Each invocation first
materializes dirList, traverses entries, then removes its parent. It never tests
deleted-state afterward. A recording-success leaf is therefore sufficient for
this sequencing question on stable ordinary non-aliased trees. Symlink aliases
can invalidate this reasoning and are excluded, together with hardlinks, mount
aliases and concurrent mutation. The auditor checks regular files, link counts,
device identity, exact file bytes and the exact directory set after every run.

Six cases, each repeated on the SAME retained tree: a one-child chain; an empty
directory that remains present; a sibling tree checked only by membership and
ancestor partial order; exceptions on the chain's first, nested-directory and
root events. Chain traces are literal descendant-to-ancestor expectations.
Sibling order is never learned from readdir. Exact repeat is an additional
observed property, not a portable promise about sibling order.

Lexical lifetime reasoning ONLY: the inner scope containing fileInDir and the
range-for temporary ends before the final remove(fileName); exceptions unwind
native C++ scopes. No String/list destructor observer exists, so no runtime
claim about invisible destruction events is made.

Run from the repository root (fresh output name required):

    python3 -B source/lab/file/removal/calibrate.py acquire build/file-lab/removal-worker-r1/acquire-r2
    python3 -B source/lab/file/removal/calibrate.py verify build/file-lab/removal-worker-r1/acquire-r2

Compilation is sequential (one job). Commands, owned empty stdin pipes, exit
codes, stdout/stderr, compiler dependencies, tools, sources, all parent objects,
preexecution artifacts and before/after hashes are sealed and reconstructed.
Failed or superseded acquisitions are retained; no cleanup occurs.

Not proved: real OS permissions, nonempty deletion, real OS deletion errors,
symlinks, races, other platforms, arbitrary resource failures, invisible
lifetimes, performance, application behavior or full filesystem equivalence.
The parent owns integration, catalog changes and final independent verification.
